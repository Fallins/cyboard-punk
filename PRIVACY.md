# Privacy

CYBOARD is designed to work locally on the user's Mac.

## Data CYBOARD may read
- local provider installation/login state;
- provider quota/reset information;
- bounded normalized quota history generated by CYBOARD;
- local process metadata needed to identify active coding-agent sessions;
- read-only provider state such as Cursor's local state database when required for quota or usage access;
- bounded local Codex/Claude usage metadata used for token/project attribution;
- bounded provider-measured Cursor usage events when Cursor exposes them through its own dashboard service.

## Data CYBOARD does not collect
CYBOARD does not operate a project-owned server, does not upload usage history to the project owner, and does not include third-party analytics or advertising SDKs. Provider network calls go only to the relevant provider endpoints or first-party localhost services required to retrieve quota/usage state.

Normalized provider usage data is displayed locally. Current `UsageSample` token activity is not copied into CYBOARD's persistent history store.

## Credentials and local session tokens
Provider credentials/session material are read and handled only by the native Rust process. They never cross the Tauri IPC boundary into the UI, are never stored in CYBOARD quota history, and are never exported in diagnostics.

When a provider requires authenticated network access, CYBOARD may present that provider's existing credential/session token only to that provider's own endpoint. For example, Cursor's existing desktop session is used in memory to authenticate requests to Cursor's dashboard usage/quota services. CYBOARD does not send provider credentials to the project owner or to unrelated third parties.

CYBOARD does not ask users to paste provider tokens into the dashboard. Provider-owned credential/state stores are treated as read-only inputs and CYBOARD never replaces or deletes those credentials.

## Token activity content boundaries
CYBOARD normalizes only usage metadata needed by the dashboard:

- Codex: thread timestamp, measured thread token total and optional project-directory basename;
- Claude Code: request timestamp, model, project-directory basename and measured input/output/cache token counters;
- Cursor: request timestamp, model and measured input/output/cache/cost fields exposed by Cursor's dashboard usage service.

CYBOARD does not expose prompt text, assistant responses, tool input/output, raw Claude transcript lines, raw authenticated provider payloads, credential file contents, session cookies or account IDs to the frontend. Cursor project attribution is not inferred when Cursor's measured usage events do not supply a trustworthy repository/workspace identity.

## Provider visibility settings
Provider visibility and Operator mode are local UI preferences stored on the user's Mac. They are not synced or transmitted by CYBOARD.

## CYBOARD Operator
The Phase 2 NYX / AXON renderer is a local visual component. The procedural WebGL renderer does not send character state, provider state, screenshots, or animation data to an external service. Future optional voice or cloud-assisted Operator features must be opt-in and documented before release.

## Retired integration research
Antigravity integration research is retained in `docs/antigravity.md`, but Antigravity is not part of the current runtime. CYBOARD no longer reads Antigravity process metadata, OAuth material, local CSRF values, or Google Cloud Code quota data.

A CYBOARD-created Antigravity Keychain item from an older development build may remain on a developer machine; current builds do not read or modify it. Credential cleanup should be an explicit user action, never a silent migration.

## Future features
Any optional cloud sync, telemetry, voice service, remote monitoring, or external model-generation feature must be opt-in and documented here before release.
