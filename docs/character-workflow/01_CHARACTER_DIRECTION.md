# 01 — Character Direction

Status: **UNLOCKED — STAGE 0 REQUIRED**

## Purpose

This file becomes the design contract after Stage 0. Until Stage 0 passes, no new character identity is considered approved.

The current production NYX is a **protected legacy baseline**, not a mandatory redesign target. The user has explicitly authorized reconsidering the character design. Stage 0 may choose to:

1. retain NYX and refine the existing identity;
2. redesign NYX substantially while keeping the role/name;
3. create a new Operator identity and retire NYX only after the final Promotion Gate.

No current production asset is changed merely by choosing a new direction.

## Existing baseline cues

Use these only as context when producing options, not as immutable constraints:

- adult, mature, semi-realistic Operator presentation;
- premium cyber-tech visual language;
- readable silhouette at dashboard scale;
- a small chest-core / signal-core motif has historically been part of the identity;
- calm, intelligent, controlled presence rather than a combat-first pose;
- the character must function as the visual embodiment of an AI signal/agent command center.

The current detailed production specification remains in `docs/nyx-2.5d-asset-spec.md` and the locked source remains in `assets/operator/nyx/source-lock.json` until a future Promotion Gate replaces it.

## Stage 0 deliverables

The Stage 0 chat must produce **3–5 clearly different directions**, not cosmetic variants of the same design.

Each direction must define:

- working name;
- role/personality in CYBOARD;
- visual archetype;
- face style and realism level;
- hair concept;
- body/silhouette concept;
- costume language;
- signature motif/core;
- primary palette and emissive palette;
- expected rendering medium(s): 2D / 2.5D / 3D exploration;
- strengths at small dashboard scale;
- animation implications;
- implementation risk/cost;
- what makes it recognizably CYBOARD rather than generic cyberpunk art.

The agent should use visual concept generation when useful, but must keep options compositionally comparable enough for the user to judge the character rather than the background art.

## Design-change policy after Stage 0

After Stage 0 PASS, changes fall into two categories:

### Refinement
Changes that preserve the selected identity. Allowed within later stages when scoped by state.

### Redesign
Changes to face archetype, core silhouette, costume language, signature motif, or overall identity. A redesign reopens Stage 0/1 and invalidates downstream visual gates as needed.

The agent must never hide a redesign inside a "small polish" task.
